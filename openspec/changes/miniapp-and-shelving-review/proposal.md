# Proposal

## Why

图书馆已有 PC Web 端（图书编目 / 借还 / 上架），但借阅者无法自助查询图书信息与所在位置、也无法随时查看自己当前在借书籍以免逾期；工作人员录入上架靠手工敲入信息，效率低且易错。同时当前上架确认后即恢复可借，缺少审核环节，无法保证位置、照片与书目信息的准确性。新增微信小程序端、AI 拍照识别与上架审核，提升借阅体验与上架数据质量。

## What Changes

- 新增微信小程序（uni-app + Vue 3，编译到微信小程序）：
  - 借阅者免登录按书名 / ISBN 查询书籍信息（书名、作者、分类、可借数量、所在位置）
  - 借阅者按借书证号查询当前在借书籍（书名、借出时间、应还时间、逾期标识），便于及时归还
  - 工作人员拍照上传书籍照片，AI 识别提取书名 / 作者 / ISBN 并自动录入馆藏（进入待上架清单）
- 新增后端书籍信息识别服务：定义识别接口抽象，MVP 先提供模拟实现返回固定识别结果，预留真实大模型接入
- 上架流程增加审核环节：上架确认后图书进入「待审核」状态，PC 端审核通过才恢复可借；驳回退回待上架清单
- PC 上架办理页新增「待审核」页签：展示待审核图书与上架信息（位置 / 照片 / 操作人 / 时间），支持通过与驳回

## Capabilities

### New Capabilities

- `miniapp`: 微信小程序端系统行为——书籍与位置查询、按借书证号查在借书籍、工作人员拍照识别录入上架
- `ai-book-recognition`: 书籍照片信息识别能力——识别接口抽象与模拟实现，识别结果用于馆藏录入

### Modified Capabilities

- `circulation`: 上架流程增加审核环节——上架确认后进入待审核，审核通过才恢复可借，驳回退回待上架清单

## Impact

- 后端：`Book` / `ShelvingRecord` 增加审核状态字段与待审核清单接口；`ShelvingService` 上架状态机调整（待上架 → 待审核 → 可借）；新增书籍识别接口（抽象 + 模拟实现）；小程序复用既有书籍检索、在借记录查询接口
- 前端 PC：`ShelvingView` 新增「待审核」页签与审核操作
- 前端小程序：新建 `miniapp/` 项目（uni-app），与后端通过 HTTP 接口交互
- 测试：`ShelvingApiTest` 新增审核用例，`BookApiTest` 断言随状态机调整

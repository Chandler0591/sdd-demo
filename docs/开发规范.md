# 开发规范（图书馆管理系统）

借鉴 AI-Product 的强制 / 推荐分级写法。违反「强制」必须修改后才合入；「推荐」是保持代码一致的默认做法。

## 一、强制（MUST）

1. **分层单向**：web(Controller) → service → repository，禁止反向依赖。Controller 只做参数校验与转发，业务逻辑全部在 service。
2. **entity 禁止直接返回**：所有 REST 接口返回 VO / DTO，映射在 service 层完成，entity 不越过 service 暴露给前端。
3. **同一本书判据（四要素）**：书名 + 出版社 + 作者 + 出版年份**全部一致**才算同一本书（见 `BookService.matchExistingByAttributes`）。任何「查重 / 复用 ISBN」逻辑必须走这个判据，不得只按书名或 ISBN 判断。
4. **数据库结构变更必须同步 `backend/db/schema.sql`**（幂等 DROP + CREATE）。测试库每次由 schema.sql 重建，只 ALTER 真实库会导致测试大范围失败。
5. **敏感信息不落仓库**：API Key 一律环境变量注入（`DASHSCOPE_API_KEY`），禁止写入代码、配置或仓库。数据库密码目前明文在 application.yml，为已知风险，仓库公开前必须改为环境变量注入。
6. **行为变更必须补测试**；禁止删断言、注释断言或跳过测试换取绿色（借鉴 AI-Product 的 xfail 哨兵思想：不允许用删测试掩盖回归）。
7. **千问识别模型固定 `qwen3.6-flash`**（qwen-vl-max 已于 2026-10 下线）；识别失败必须返回用户友好的中文提示（BusinessException），不裸抛第三方错误。

## 二、推荐（SHOULD）

1. **命名语义化**：Repository 查询方法用 `findByXxx`（单字段）/ `matchXxx`（多字段判据）；Service 公开方法名与 Controller 动作一致（search / create / update / addCopies）。
2. **注释**：中文，密度与周围代码一致；公共 API 方法写一行 Javadoc 说明用途。
3. **错误提示**：面向馆员 / 读者的中文提示，避免裸异常信息或英文堆栈。
4. **测试覆盖**：新增 REST 接口在 `BookApiTest`（或对应模块测试）补集成测试；纯解析 / 工具逻辑补单元测试（参考 `QwenBookInfoRecognizerTest`）。
5. **幂等**：DDL、脚本、初始化数据均需可重复执行，重复运行结果一致。
6. **外部依赖少**：优先用框架自带能力（如 RestClient 直调外部 API），不轻易加新依赖。

## 三、提交与文档

- 提交前跑完整测试（当前 52 个单测）。
- 开发中踩到新坑：追加进根目录 `AGENTS.md` 的「易踩坑清单」，并更新「权威文件索引」。
- 接口有增删改：PC 端与小程序同步适配；若属已规划的 OpenSpec 变更，勾选对应 tasks.md 任务项。
- 数据库结构变更：同步 schema.sql 后，如有设计文档一并更新。
